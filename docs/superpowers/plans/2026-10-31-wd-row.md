# WD (whole day) fourth row Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every department planner gets a fourth row per person, WD (whole day), for ground and admin items, plus a UI zoom control and a stronger divider between crew.

**Architecture:** First a behaviour-preserving refactor of the dashboard so crew rows come from one helper (`gridRow`) and one constant (`ROWS_PER`), proven by the existing suites. Then the builder writes four rows and layout stamp 3, and the dashboard flips `ROWS_PER` to 4 and adds the WD cells, Ops Room column, My Lodestar items, zoom and divider. Fresh files are built into a scratch folder; the repo's own `.xlsx` files are not touched.

**Tech Stack:** `.build_planner.py` (openpyxl), `.dashboard_source.html`, Node + Playwright tests, `.lodestar_build.py`.

**Spec:** `docs/superpowers/specs/2026-10-31-wd-row-design.md`

## Global Constraints

- Offline, macro-free `.xlsx`; ship the dev build; bump the version string to `Dashboard version 2026-10-31 z103` in both places (`#wDiag`, `spDiag`) and update the two `version_is_z10x` tests.
- Layout stamp: department files `dept 2` to `dept 3`; dashboard `LAYOUT.dept = 3`. Master, roster and ops stamps stay.
- **Never overwrite an `.xlsx` in the repo folder.** Build into a scratch folder (below) and point tests at it with `LODE_FILES`. Replacing the repo's files is Task 8 and needs Brandon's go-ahead.
- WD accepts activities of categories Ground Duty (`CAT_GD`) and Admin (`CAT_ADMIN`) only. Flights, Sim, leave, off, medical, oversea, duty and standby stay in rows 0 to 2. Currency, crew rest, down-chit, Ops Room crew pick and syllabus code keep reading rows 0 to 2.
- WD colours: label `CCFBF1` with text `115E59`; empty-row tint `F0FDFA`. Divider: 3 px `#0f172a` top border on each person's first row.
- Zoom levels 100 / 90 / 85 / 80 / 75 %; default 85 % on the planner, 100 % elsewhere; the Ops Room tab always 100 % (it keeps its own zoom).
- Wording: 121 SQN is one squadron; plain English.
- Scratch folders: `SCR=/tmp/lodestar_wd`; demo set `$SCR/demo`, real-data set `$SCR/real` (`--data input/LODESTAR_Data_Input.xlsx`).

## Review Focus

- A layout-2 file (3 rows per person) opened by the new dashboard: it must show the "older layout" warning and not draw a scrambled grid or write to wrong cells.
- A flight code pasted into a WD cell (validation bypassed): it must not count as a flight, hours, currency or crew rest, and must not seat on the Ops Room.
- A crew member hidden by the Excel filter (empty slot): all four of their rows hide, and "unhide new crew" on save reveals all four.
- Ground item in AM and in WD on the same day: one ground-duty day, not two.
- A corrupt or missing saved zoom value in the browser: falls back to the default without an error.
- Many WD items on one day in the Ops Room "Whole day" column: wraps, does not push the AM / PM / NIGHT columns off screen.
